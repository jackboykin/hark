# cache write-amplification baseline (post D5 shared-owner-name pack)
# build=ReleaseFast, single thread, M=1000 stores per combo
# Backing allocator wrapped by AllocCounter; cache CountingAllocator
# forwards every alloc call, so calls/store is exact for the cache path
# (slot key dup + records array + shared name backing + per-record wire
# + per-record rdata clone + cached_sigs/cached_proofs slots).
#
# Read path baseline (cache_hit): 2 allocs / lookup regardless of N.
#
# D5 (shared owner-name backing): records[] in an RRset now share a single
# cloneNameFlat-style allocation. Saves (label_count + 1) × N − 1 allocs per
# RRset relative to the pre-D5 per-record cloneName, where label_count is
# the owner-name label count (3 in this bench).
#
# Pre-D5 vs post-D5 allocs at N=8:
#   a/aaaa         42  →  11   (−74%)
#   cname/mx       74  →  43   (−42%)
#   nsec           82  →  51   (−38%)
#   dnskey+rrsig  123  →  92   (−25%)
# Proportional gain falls for types whose rdata holds child names
# (cname target, mx exchange, nsec next-name, rrsig signer/keys) — those
# still get per-record cloneName in cloneRData. Owner-name sharing is the
# bound of D5's scope.
#
# Throughput moved with allocs: a/N=8 went 23k → 35k ops/s (+50%).
#
